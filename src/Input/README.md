# Input Module

The input layer translates SDL events into grid camera movement, layout edits, selection workflows (click, marquee, and multi-anchor drag), and editor state updates.

## Files
- `input_handler.h` / `input_handler.c` — central dispatcher invoked from `main.c`. It asks `Global_RebuildHitboxesIfDirty()` for fresh hitboxes before forwarding events to the device-specific handlers and routes `SDL_TEXTINPUT` / mouse motion into the UI layer so save/root text dialogs and other panel overlays can react.
- `input_routing_policy.h` / `input_routing_policy.c` — explicit top-level `IR1` normalize-policy seam for classifying raw events into action class + route policy with text-entry/global-shortcut precedence (`Esc` global only when text capture is inactive).
- `input_viewport_pick.h` / `input_viewport_pick.c` — shared viewport pick resolver for object-workspace hover/click. It records pane lane, raw hitbox winner, exact Edge/Vertex topology hit, filtered hit, body fallback result, final hit, topology-mode state, and a reason enum so hover and click consume one object-edit-mode policy instead of duplicating topology/body fallback filtering. The resolver also stores the latest pick and exposes compact labels used by the object-mode status overlay (`pane`, `raw`, `exact`, `final`, `why`, `attach`, `topo`) while the topology input lane is being stabilized.
- `input_viewport_navigation.h` / `input_viewport_navigation.c` — app-local CV3D3 mouse adapter. It maps Alt/Option+LMB orbit and MMB pan into shared `core_viewport3d` commands while preserving LineDrawing's durable target/Grid storage rules and yielding to splitters, panes, authoring, modals, selection boxes, and active handle/gizmo/object drags.
- `input_mouse.h` / `input_mouse.c` — main mouse-event shell. It now owns free-view orbit motion, mouse wheel zoom, left/right button routing, and public `Input_MouseHandle(...)` dispatch, while still driving lasso selection, drag-to-pan, handle/gizmo manipulation, wall placement, and the high-level viewport mutation flow through the existing editor/layout APIs. Wheel zoom still lets the left `Scene` list consume wheel input first when that shell tab is active; otherwise zoom routes through `Core/viewport_zoom` so large enabled scene bounds can lower the zoom-out floor enough to remain visible. In `SPACE_MODE_3D + FREE_VIEW`, clicking a gizmo axis handle starts an axis-constrained drag session with signed motion from drag-start, default grid-step quantization, and `Shift` smooth override; undo is captured once at drag start for mutating targets and the session closes on mouse-up. `LD3D-F4` adds hover/select routing for plane primitive hitboxes (`HITBOX_OBJECT3D`) so authored planes can be selected from the viewport. `LD3D-F4.5` adds direct plane resize drags from viewport handles (`HITBOX_OBJECT3D_PLANE_CORNER` + `HITBOX_OBJECT3D_PLANE_EDGE`) with one undo capture per drag and `Alt` smooth override (`default = snapped`). The post-foundation manipulator lane extends plane handles in free view: clicking a plane edge/corner selects the handle, legal local `U/V` gizmo axes appear, and axis drags resize through `Layout_ResizePlanePrimitiveFromHandle(...)` while plane-view direct resize remains intact. Scene-bounds handles now follow the same select-then-axis-drag pattern: clicking a bounds face, edge, corner, or center selects it; legal gizmo endpoints appear for resize or whole-bounds translate; and constrained drags mutate `scene3d.bounds` through `Layout_ResizeSceneBounds3DFromHandle(...)` or `Layout_TranslateSceneBounds3D(...)` while typed `BMin`/`BMax` dialogs remain exact-entry fallbacks. `LD3D-F5.3` extends prism editing in two lanes: direct handle drags for local `W/H` resize, plus free-view constrained prism-handle gizmo drags (`HITBOX_OBJECT3D_GIZMO_AXIS`) where corner handles allow local `U/V/N` motion, edge handles allow two-axis motion (in-plane normal + `N`), and depth edits route through the dedicated depth-resize layout API. `LD3D-F7` adds object-rotation drag on center gizmo axes when gizmo mode is set to rotate (default snapped to `15°`, `Shift` free rotation), with deterministic baseline-to-angle composition for stable persisted orientation. Phase D topology selections now route selected object-authoring vertices/edges into the same constrained-gizmo click lane, but those target drags are non-mutating until semantic topology operations exist. Edge/Vertex mode blank or non-topology clicks preserve the active object-workspace body and clear only the topology/face target back to body selection instead of ejecting to scene selection; those modes also suppress body-center gizmo fallback and primitive resize handle picks until an actual topology vertex/edge is selected. Edge/Vertex center-viewport clicks get first chance at topology selection before HUD or face-authoring handlers, and Edge mode uses visible midpoint handles that match the emitted edge hitboxes. It also calls `UIPanel_HandleClick` so UI interactions short-circuit layout edits and raises `Global_FlagGridChanged` whenever panning/zooming alters the camera.
- `input_mouse_hover.c` / `input_mouse_internal.h` — extracted hover and pointer-lane seam for the mouse path. These files now own pane-lane routing, hover clearing and rebuild, nearest-object/object-face hover resolution, object-authoring hover policy, and the private helper contract shared with the surviving shell. Object edit modes now filter topology hover before generic body/face hover: Edge mode resolves edge topology only, Vertex mode resolves vertex topology only, face hover is suppressed outside Face mode, and the nearest-object body fallback is blocked when Edge/Vertex mode misses topology. Edge/Vertex hover now uses the same topology-first rule as click selection, so free-view body picking cannot overwrite an exact topology handle hover.
- `input_mouse_drag.h` / `mouse/input_mouse_drag.c` — shared mouse-drag session helpers extracted from the main mouse handler. Owns object/anchor drag lifecycle slices, drag-state transitions, and the bounded helper contracts shared across viewport drag modes. Object handle-gizmo drags now store one normalized `ObjectHandleGizmoTarget`, letting plane/prism resize handles and object-authoring topology targets share the same begin/update path. Topology targets can become active/hovered axis sessions but skip history capture and mutation until the authoring document grows semantic topology edit operations. Scene-bounds gizmo drags use their own small drag state so AABB face/edge/corner resize and center translate edits do not overload object manipulation state.
- `input_keyboard.h` / `input_keyboard.c` — polls held keys for continuous panning and zoom, toggles the global quit flag on `Esc`, and reacts to discrete key presses: `M` toggles `SpaceMode` (`2D`/`3D`) with persistence, `X` cycles object center-gizmo mode (`Move`/`Rotate`/`Size`), `H` toggles scene-bounds edit handle visibility without changing persisted bounds, `Shift` constrains wall placement (and signals shift state to the editor for marquee activation), `D` toggles delete modes, `1/2/3` switch active edit planes (`XY/YZ/XZ`), `[`/`]` adjust active plane offset, `O` recentres the grid on the selected anchor, `P` toggles anchor persistence, `Shift+P` creates a plane primitive on the active construction plane (`Alt+Shift+P` disables bounds lock for that creation), `Shift+R` creates a rectangular prism primitive (`Alt+Shift+R` disables bounds lock for that creation), `Shift+C` toggles center crosshair visibility, `C` converts anchors between corner/curve, `L` toggles linked handles, and `Delete/Backspace` remove the selected wall, anchor, or selected 3D object. The same object-creation paths are available from right-panel buttons (`Add Plane`, `Add Prism`), selected prism dimensions can be edited via right-panel buttons (`Prism W`, `Prism H`, `Prism D`) using typed dialogs, scene bounds can be toggled/edited from right-panel bounds controls (`Bounds`, `Clamp`, `Edit BMin`, `Edit BMax`, `Fit B->Obj`), and display units can be cycled from the `Units` button for unit-aware dimension/bounds entry-display. `Ctrl/Cmd+Z` performs undo, `Ctrl/Cmd+Shift+Z` or `Ctrl/Cmd+Y` performs redo, `Ctrl/Cmd+B` (`Shift` variant for output root) opens native root folder choosers, and `Ctrl/Cmd+I` / `Ctrl/Cmd+O` open typed root edit dialogs. The handler defers to the panel when save/root/dimension/bounds dialogs are capturing keyboard input.

## Interactions
- Mouse and keyboard handlers depend on `Global_Get()` to access the grid, layout, and editor. The mouse path now mirrors editor functionality: shift starts marquee selection, Alt overrides snapping during drags, and multi-selection data is stored in `EditorState`.
- During the 3D migration phase, mouse picks are now resolved against the active edit plane using shared ray/plane helpers, then flow through 3D-ready editor/layout APIs.
- `SpaceMode` constraints are enforced in input:
  - `2D` mode locks editing to `XY@z=0` and blocks free-view/plane-switch controls,
  - `3D` mode enables free-view and plane controls.
- Input projection/mapping now flows through `Core/adapters/space_mode_adapter.c` (via `space_mode_adapter.h`) so mode-aware plane/camera behavior is shared with render and hit-test code.
- Curved-handle dragging now derives polar handle values from world-space deltas projected onto the active edit plane, so handle edits remain plane-local and camera-independent.
- In `FREE_VIEW`, Alt/Option+LMB orbit preserves the current target; MMB pan changes that target in camera screen space. Empty-space LMB pan and precise Alt handle/gizmo drags keep their established authoring priority.
- While a gizmo drag session is active, orbit is suppressed so axis-constrained editing is not interrupted.
- While a plane/prism-resize drag, plane/prism handle-gizmo drag, or scene-bounds handle-gizmo drag is active, orbit is suppressed so handle editing remains stable.
- Overlap resolution still relies on ranked hitbox picking for handles, points, walls, and gizmo lanes, but plain object-body hover/click is now resolved through nearest projected object origin so overlapping object bounds do not dominate dense-scene selection.
- `Global_RebuildHitboxesIfDirty` centralises hitbox regeneration so the input layer never runs stale selection or handle hit-tests.
- Workspace Authoring is routed before focused editor input: `Alt+C` then `Alt+V` toggles authoring through the shared `kit_workspace_authoring` chord helper, `Tab` cycles draft overlay modes, `Enter` applies, and `Esc` cancels active authoring before the global quit route sees the key. While authoring is active, mouse motion and left clicks are captured by the authoring host so shared overlay button and Font/Theme panel hit testing can drive Mode/Apply/Cancel plus text/font/theme preview controls without leaking clicks into layout editing.
- UI button actions triggered from `UIPanel_HandleClick` call into layout persistence, root-path controls, grid zoom helpers, editor mode toggles, history capture, and now the left-scene object list selection lane (raising the relevant dirty flags as needed). Save/root dialogs and native file/folder chooser flows consume input so accidental layout edits are avoided while typing or choosing configs.
