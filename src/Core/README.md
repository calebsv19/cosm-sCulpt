# Core Module

The core layer owns application-wide state and the SDL boilerplate so other systems can stay focused on the top-level host and layout-editing runtime.

## Files
- `global_state.h` / `global_state.c` — allocate and expose the singleton `GlobalState`, initialise the grid, layout, editor, and UI panel, and provide helpers such as `Global_GetScreenWidth`. Dirty flags (`layoutDirty`, `layoutDirtySinceSave`, `hitboxDirty`) plus the helpers `Global_FlagLayoutChanged`, `Global_FlagGridChanged`, and `Global_RebuildHitboxesIfDirty` keep hitboxes in sync while avoiding unnecessary rebuilds. Persistence helpers (`Global_OnLayoutSaved`, `Global_OnLayoutLoaded`, `Global_GetCurrentConfigPath`, `Global_IsLayoutDirty`) track the active layout file and whether the in-memory state has diverged from disk. Startup now also seeds `lastLayoutPath` and `lastSceneAuthoringPath` from recent-context history so the file-pane restore lane can reopen the last relevant session, and session input-root edits now preserve a real loaded layout identity instead of overwriting it with the new root's default `layout_config.json` path. Runtime mesh session fields (`lastObjectRuntimeMeshPath`, `objectRuntimeMeshStatus`) are also mutated through Core-owned `Global_*ObjectRuntimeMesh*` helpers so File-pane export/import code owns wording and operations while Core owns storage. `SpaceMode` state (`2D`/`3D`) is now owned here, including startup persistence via `config/space_mode.txt` and mode-constraint enforcement.
- `line_drawing_startup_config.h` / `line_drawing_startup_config.c` — app-local lifecycle/config diagnostic helper for startup data-root fallback. It applies unset/missing input, output, layout, and object-asset root fallbacks while returning a structured per-root report (`unchanged`, `unset`, or `missing`) so tests can assert startup decisions without scraping stderr. `Global_Init(...)` remains responsible for persistence and user-visible `[startup]` logging.
- `line_drawing_file_catalog.h` / `line_drawing_file_catalog.c` — app-local layout/package discovery contract for the host menu and editor file browser. Authoring-only packages are discoverable before their first runtime compile; descriptor validation and legacy fallback route through `sculpt_scene_package.*`.
- `sculpt_scene_package.h` / `sculpt_scene_package.c` — Sculpt-owned `sculpt_scene_package_v1` schema, stable scene-id derivation, atomic descriptor writer, and safe resolver for package directories, descriptors, canonical authoring files, and legacy loose-layout JSON. Compiled runtime JSON is explicitly rejected as editable input.
- `scene_document_lifecycle.h` / `scene_document_lifecycle.c` — app-local document identity and scene-package lifecycle policy. It distinguishes untitled layouts, layout JSON documents, canonical scene authoring, and object assets; reports runtime freshness; and implements collision-safe Scene Save As. A clone allowlists authoring-owned `assets/` and `attachments/`, then creates a fresh descriptor while omitting runtime, dependency, receipt, project, and cache outputs.
- `line_drawing_pane_host.h` / `line_drawing_pane_host.c` — app-local pane-host seam built on shared `core_layout`, `core_pane`, and `core_pane_module`. Seeds the canonical 4-lane UI graph (`top bar`, `left controls`, `center canvas`, `right controls`), validates/solves leaf rectangles, and validates role module bindings for deterministic pane geometry ownership.
- `workspace/line_drawing_workspace_mode_handoff.c` — owner for Scene/Object workspace document handoff. It captures, restores, and reseeds scene/object document snapshots, document identity paths, dirty-since-save state, viewport state, selected object/asset face, and ObjectAuthoring session state when `Global_SetWorkspaceMode(...)` crosses workspaces. Keep behavior changes test-first in `tests/test_layout_object3d_store.c`.
- `workspace/line_drawing_object_workspace_view.c` — owns object-workspace view/selection coordination that must update durable `ObjectAuthoringSession` state and transient `EditorState` mirrors together. Use helpers such as `LineDrawingObjectWorkspaceView_SelectBody(...)`, `LineDrawingObjectWorkspaceView_EnterFreeView(...)`, and `LineDrawingObjectWorkspaceView_FocusFace(...)` instead of duplicating ObjectAuthoring/editor selection writes in UI surfaces.
- `space_mode_adapter.h` / `adapters/space_mode_adapter.c` — central mode-aware adapter seam for projection/view context. It builds a single `SpaceViewContext` that normalizes runtime behavior (`2D` lock or `3D` free-view) and exposes shared helpers for projection and screen-to-world conversion used across input/editor/layout/render paths.
- `viewport_zoom.h` / `viewport_zoom.c` — app-local zoom policy around `Grid_zoom_clamped(...)`. It keeps generic grid math in the grid module while deriving the zoom-out floor from enabled, valid `scene3d.bounds` projected through the current plane/free-view camera into the center canvas viewport.
- `viewport3d_bridge.h` / `viewport3d_bridge.c` — thin CV3D3 adapter between LineDrawing's float-degree `FreeViewCamera` + Grid storage and shared `core_viewport3d >= 0.1.0`. It derives the canonical effective viewport-center target from camera target, basis, Grid offsets, pane center, and pixels-per-world scale, including old-to-new pane-center compensation on resize; LineDrawing retains storage, projection, input, and authoring policy.
- `viewport_navigation_contract.h` / `viewport_navigation_contract.c` — retained EVN2 oracle and local command vocabulary. Shared `core_viewport3d` now owns free-view pan/orbit/anchor-zoom/frame transitions, while this contract remains focused parity/rollback evidence until CV3D4 hands-on acceptance.
- `SDLApp/` — SDL wrapper providing the runtime loop with mode-aware wait policy, render-on-dirty heartbeat behavior, and loop diagnostics emission (see `SDLApp/README.md` for details).

- `editor_preferences.h` / `editor_preferences.c` — app-owned presentation preferences.
  The main lifecycle restores units, named/free view, yaw/pitch and navigation tool,
  then saves on normal shutdown using shared `core_io` atomic writes. Bounded strict
  JSON parsing rejects invalid files as a whole. No physical document or history edit
  is performed; 2D locks remain enforced and line drawing never launches armed.

## Interactions
- Input, rendering, layout, and UI code call `Global_Get()` to access shared state instead of passing references around.
- Window resize events captured in the SDL loop call `Global_SetWindowSize`, which keeps the UI and grid aware of the current renderer size.
- Systems that mutate layout geometry call `Global_FlagLayoutChanged`, while view/navigation code calls `Global_FlagGridChanged`; both funnel into `Global_RebuildHitboxesIfDirty`, which compacts layout deletions on demand before regenerating selection hitboxes.
- Window-size updates now also rebuild the pane-host solve so pane leaf rectangles stay synchronized with runtime bounds.
- Save/load UI paths call `Global_OnLayoutSaved` / `Global_OnLayoutLoaded` so the info overlay and undo history know which config file is in play and whether a rename prompt should appear.
- `Global_Shutdown` first waits for any active File-pane async STL import
  worker through `UIPanel_WaitForAsyncStlImport(...)`, then releases layout,
  editor, workspace document, and object-authoring resources. It is
  idempotent so partial lifecycle cleanup can call it safely.
- `src/main.c` now composes this shared runtime state behind a host-level `MENU` vs `EDITOR` mode split rather than treating the editor as the only boot surface.

- `camera_path.*` owns exact-point draft/Apply transactions and transient timed preview; `camera_path_proof.*` supplies bounded native full-van and real-demand-loop proof modes.
