# Editor Module

The editor layer manages the wall-placement workflow, bezier anchor editing, multi-anchor selection/dragging, and overlay rendering for in-progress actions.

Whole-object 3D hover/click uses the projected visual center of each eligible
object through shared `core_screen_pick >= 0.1.0`. The app rebuilds that index
with its hitbox lifecycle and retains FreeViewCamera/Grid projection, gizmo and
resize-handle priority, topology picking, authoring arbitration, and rendering.

## Files
- `editor.h` / `editor.c` — define `EditorState`, track the current tool mode, anchor/hover selections, object-handle selections, scene-bounds handle selections, scene-bounds handle visibility, delete mode, shift-state, marquee selection bounds, and multi-selection arrays. Maintain undo/redo stacks (JSON snapshots of the layout), expose `Editor_HistoryCapture`, `Editor_Undo`, `Editor_Redo`, `Editor_ClearHistory`, and implement helpers for selection editing (`Editor_SelectAnchor`, `Editor_SelectAnchorsInBox`, `Editor_BeginAnchorDrag`, etc.). The placement and drag paths are now 3D-ready (`Vec3` world positions), while current interaction behavior remains XY-constrained for compatibility. Projection/plane semantics now flow through `space_mode_adapter` so editor selection and placement use the same mode-aware view context as input/render.
- `object_handle_gizmo.h` / `gizmo/object_handle_gizmo.c` — app-local manipulator target contract for selected plane/prism resize handles and selected object-authoring topology refs. Normalizes selected editor handles or `ObjectAuthoring` vertex/edge selections into an `ObjectHandleGizmoTarget`, exposes legal axis masks, handle/world target points, axis vectors, drag-handle resolution, and resize mutation for primitive handles so hitbox, render, and input drag paths do not duplicate plane-vs-prism policy. Topology targets currently provide visual/clickable constrained axes but are deliberately non-mutating until a semantic topology operation lands.
- `object_face_sketch.h` / `object_face_sketch.c`, `object_face_sketch_edit.h` / `object_face_sketch_edit.c`, and `object_face_extrude.h` / `object_face_extrude.c` — object-workspace face authoring controls for the current rectangle-sketch and bounded extrude proof. These paths now write committed rectangle sketches and extrude intent/result records into `ObjectAuthoringSession`; attached extrude commits append semantic operations, evaluate the authoring document, and rebuild `Layout.objectStore` from evaluated primitive bodies. Committed sketch render/hitbox paths prefer the authoring document, while `EditorState` sketch/extrude fields remain as transient input, preview, and UI compatibility mirrors. Live extrude-preview depth is now adjusted through editor helpers (`Editor_ObjectFaceExtrudeSetDepth` / `Editor_ObjectFaceExtrudeAdjustDepth`) so UI parameter controls do not mutate preview state ad hoc.
- `primitive_placement_preview.h` / `primitive_placement_preview.c` — app-local primitive placement contract shared by preview rendering and actual plane/prism creation. Resolves the active construction-plane frame, center-screen spawn origin, default grid-scaled dimensions, and preview corners so ghost geometry matches the object that will be created.
- `render_editor.h` / `render/render_editor.c` — render helper functions: `Render_Editor_Anchor` shows the starting anchor while placing a wall, `Render_Editor_GhostWall` draws the snapped preview line (respecting shift locking), `Render_Editor_SelectionBox` draws the translucent marquee while lasso selecting, and `Render_Editor_AxisGizmo` draws free-view axis gizmos with hover/active visual states. The axis renderer now covers selected anchors, object center move/rotate handles, selected prism resize handles, selected plane resize handles, selected object-authoring vertex/edge targets, and selected scene-bounds handles; topology targets render legal local axes at the selected vertex or edge midpoint without mutating geometry yet. Plane handles render only their legal local `U/V` resize axes, while scene-bounds handles render one, two, or three legal world `X/Y/Z` axes depending on whether the selected bounds handle is a face, edge, corner, or center translate handle. `Render_EditorOverlay` bundles overlay calls. A placeholder exists for future selected-wall highlighting.
- `space_gizmo_drag.h` / `gizmo/space_gizmo_drag.c` — contracts for free-view 3D axis-gizmo drag math and session state (`+/-X`, `+/-Y`, `+/-Z`). Exposes signed mouse projection, world-distance conversion, quantized-vs-smooth resolution, and axis-distance application helpers used by upcoming gizmo input/hitbox slices.
- `scene_authoring_path_handles.h` / `scene_authoring_path_handles.c` — app-local camera/light/generic path, camera-aim, and light-position/aim viewport handles. Cubic paths expose typed anchors, incoming/outgoing tangents, and segments; tangent connector rails and compact markers stay screen-stable, segment/handle hover is persistent editor state, and selected draggable handles receive the same zoom-stable center/X/Y/Z gizmo. Typed picks persist through mouse-down and drag sessions. Center drags remain construction-plane movement; X/Y/Z drags use baseline-relative projected motion and mutate only the selected world coordinate. Light previews resolve independent or path-start position and draw authored point radius, spot cone, or area size plus persistent aim feedback.

## Interactions
- `Input_MouseHandle` calls `Editor_ClickAt` on right-clicks with grid-snapped positions, feeds hover information back into `EditorState` (including gizmo-axis hover lane in free-view), and now drives selection workflows (shift-click, marquee, double-click focus, Alt drag). In `SPACE_MODE_3D + FREE_VIEW`, gizmo-handle click starts an axis-constrained drag session that uses signed drag distance, default grid quantization, and `Shift` smooth override before routing through `Editor_UpdateAnchorDrag`. The editor exposes helper APIs so the input layer can add/remove anchors without duplicating array logic.
- `Input_KeyboardHandle` toggles `shiftHeld`, delete modes, origin shifting, pinning, converts anchors between corner/curve modes, toggles linked bezier handles, deletes selected elements, and wires `Ctrl/Cmd + Z` / `Y` into the undo stack.
- UI buttons (load/save JSON, reset origin, pin anchor, link handles, zoom) call `Editor_HistoryCapture` before mutating the layout so operations remain reversible, and invoke `Editor_ClearHistory` when a new config is loaded or saved as a baseline.
- `Render_Frame` invokes the overlay functions so the editor feedback (ghost walls, marquee, drag colouring) appears between layout drawing and UI rendering. The info overlay pulls selection/handle metadata from `EditorState` to display group counts, drag mode, and bezier values.
- `Layout/scene/layout_scene_path_geometry.*` owns the app-local evaluated path
  contract used by scene-authoring rails and insertion: linear paths emit their
  authored points, complete cubic Bezier chains use a `3n+1` control layout and
  24 samples per segment, incomplete legacy Bezier chains fall back visibly to
  linear geometry, and De Casteljau splitting preserves a cubic curve when a
  point is inserted from the viewport.
- `Layout/scene/layout_scene_path_edit.*` owns semantic `3n+1` editing above
  evaluated geometry: typed element classification, per-anchor linked, broken,
  automatic, smooth, and corner modes, mode-aware anchor/tangent mutation,
  curve-preserving split insertion, and structure-preserving anchor/segment
  deletion. Tangent modes persist in layout JSON and canonical scene export.
- `Layout/scene/layout_scene_light_authoring.*` owns renderer-neutral editable
  light defaults, independent/path-start position resolution, persistent
  world-space aim targets and effective direction, plus bounded inspector
  presets for color, intensity, radius/area size, spot cone, and falloff.
- Object workspace CAD state is moving out of broad editor ownership. `src/ObjectAuthoring/` now owns the object-authoring document/session contract; editor fields should be treated as transient controls or compatibility mirrors unless the data is explicitly input-only.
